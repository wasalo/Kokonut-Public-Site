All Kokonut DAO proposals follow the ten-field template defined in the [Governance Framework](/ecosystem-wiki/the-kokonut-dao/governance-framework). Each proposal type extends the base template with fields specific to its domain.

Before submitting any proposal:

1. Copy the relevant template below
2. Replace every `[PLACEHOLDER]` with real content
3. Leave the template open for the mandatory **5-day drafting window** so vote-authorized members can give feedback
4. After the drafting window closes, a proposal-authorized person sponsors it to the active voting stage on [DAOHaus](https://link.kokonut.network/dao)

<Tip>
  Not sure which template to use? Farm operators and community members building new production sites use **Farm Funding**. Guild Stewards commissioning work from contributors use the **Guild Bounty**. Core Team or Technology Guild members proposing changes to the Framework spec use **Framework Upgrade**. Anyone proposing a formal relationship with an external organization uses **Partnership**.
</Tip>

## Guild Bounty Proposal

Use this template when a Guild Steward is requesting a DAO treasury disbursement to fund a scoped piece of work to be completed by a contributor. Bounties are the primary mechanism by which Guild members earn stablecoins for work that benefits the ecosystem.

Bounties under **500 and above** require this full proposal and a DAOHaus vote.

```markdown
[YYYY-MM-DD]
```

## Framework Upgrade Proposal

Use this template when proposing a change to any component of the Kokonut Framework — the Common Data Schema, MRV methodology, development phases, regeneration principles, governance parameters, or ecological impact framework integrations.

Framework upgrades are the highest-sensitivity proposal type because they affect every farm currently operating under the Framework. **Any change that modifies an existing field name, type, or required status in the Common Data Schema requires a migration plan** — farms already running against the schema cannot be broken without a deprecation path.

```markdown
# [PROPOSAL NAME]
# e.g. "KFP-003 · Framework Upgrade — Add Drone Imagery CID to MRV Remote Sensing Schema"
 
---
 
## A. Proposal Name
[Short, descriptive name. Convention: KFP-[number] · Framework Upgrade — [Component]: [Change]]
 
## B. Proposal Author(s)
- Name / alias:
- Wallet address:
- Guild affiliation: [Technology / Impact / Governance / other]
 
## C. Proposal Team
List everyone involved in designing, reviewing, and implementing this change:
- [Name] — [Role: e.g. Schema Author, Farm Operator Impact Reviewer, Documentation]
- [Name] — [Role]
- **Reviewing Guild:** [Guild responsible for technical review before DAO vote]
 
## D. Draft Start Date
[YYYY-MM-DD]
 
---
 
## E. Proposal Description
 
### Change summary
| Field                     | Value                                                                       |
|---------------------------|-----------------------------------------------------------------------------|
| Framework component       | [Common Data Schema / MRV Payload / Development Phases / Governance / EBF] |
| Change type               | [additive / modification / deprecation / removal]                           |
| Backward compatible       | [Yes / No / Partial — see migration plan]                                   |
| Farms currently affected  | [List farm_ids or "All registered farms"]                                   |
| Agents currently affected | [List agent names or "None" or "All MRV agents"]                            |
| API version impact        | [None / Minor (new optional field) / Major (breaking change)]               |

or section. If this is a schema change, paste the current field definition.

- Existing EAS attestation schemas on Gnosis Chain or Base
 
If the change is additive with all new fields optional: state this clearly.
If any existing field is renamed, retyped, or removed: a migration plan is

|--------------------|-----------------------------------------------|------------------|------------------|

| Dual-write period  | API accepts both old and new formats          | Technology Guild | [N weeks]        |
| Farm migration     | Each farm updates their data submission       | Farm operators   | By [YYYY-MM-DD]  |
| Agent migration    | Each agent updates capability manifest        | Agent operators  | By [YYYY-MM-DD]  |
| Cutover            | Old format no longer accepted                 | Technology Guild | [YYYY-MM-DD]     |
 
Farms and agents that have not migrated by the cutover date will receive
```

| --- | --- | --- | --- | --- |
| **Naming convention** | KDP-N | KBP-N | KFP-N | KPP-N |
| **Treasury disbursement** | Always | If \>= \$500 | Sometimes | Sometimes |
