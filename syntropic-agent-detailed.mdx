# One agent. Many chains. Real-world regeneration.

**Kokonut Syntropic Agent** is Kokonut Network's first named AI Core Team agent and the proposed intelligent orchestration interface for the Kokonut ecosystem.

Its mission is to **develop and power real-world economic flywheels through syntropic farming and the Kokonut Framework**—connecting field work, community coordination, operational intelligence, responsible financing, and blockchain infrastructure without making farmers manage all that complexity themselves.

The Syntropic Agent is designed to work across networks through **Kokonut Protocol's NEAR-based interoperability hub**, while keeping capabilities and economic arrangements native to the networks where they are useful.

## Why this agent exists

A productive regenerative farm needs more than an agricultural recommendation. It requires planning, evidence, people, capital, logistics, monitoring, and timely decisions. Each responsibility is handled by different local actors and technical systems.

The Syntropic Agent aims to make those systems easier to coordinate by helping teams:

- turn field records into review-ready operational recommendations;
- discover gaps in agronomic, ecological, and financial evidence;
- prepare scoped plans and budgets for productive assets;
- track milestones and surface delays or inconsistencies;
- package approved information for partners, public reporting, and agent-to-agent services;
- prepare cross-chain actions for explicit human or DAO authorization.

**The agent assists with coordination. Farm operators, reviewers, legal entities, and governance bodies retain their respective authority.**

## How the system fits together

The agent is an **orchestrator**, not another canonical database, a sovereign treasury, or a replacement for Kokonut Protocol.

~~~mermaid
flowchart TD
    PEOPLE["Farm operators · Core Team · Community"]
    AGENT["Syntropic Agent — Hermes runtime"]
    KI["Kokonut Intelligence — governed data"]
    PROTOCOL["Kokonut Protocol — policy and execution"]
    NEAR["NEAR Hub — Chain Signatures"]
    BASE["Base — Virtuals / agent commerce"]
    GNOSIS["Gnosis — existing DAO and Safe"]
    CELO["Celo — EAS provenance"]
    FUTURE["Additional approved chains"]
    FARMS["Adelphi · Terra Viva · future projects"]

    PEOPLE --> AGENT
    FARMS --> KI
    AGENT <--> KI
    AGENT -->|"proposals, not self-approval"| PROTOCOL
    PEOPLE -->|"independent authorization"| PROTOCOL
    KI <--> PROTOCOL
    PROTOCOL --> NEAR
    NEAR --> BASE
    NEAR --> GNOSIS
    NEAR --> CELO
    NEAR --> FUTURE
    KI --> FARMS
~~~

| Layer | Responsibility |
| --- | --- |
| **Hermes / Syntropic Agent** | Reason, research, plan, summarize, coordinate, draft, and monitor approved scopes |
| **Kokonut Intelligence** | Canonical operational records, finance, evidence, identity context, review, and audit |
| **Kokonut Protocol** | Chain-neutral requests, execution policy, approved deployments, and reconciliation |
| **NEAR Web3 Hub** | Governed signing orchestration and NEAR-native integrations |
| **Destination chains** | Local rights, smart contracts, token settlement, attestations, and DAO state |
| **Local people and organizations** | Physical operations, financial approvals, legal duties, and evidence verification |

**A Chain Signature is not a completed transaction.** The Protocol must separately assemble, simulate, broadcast, confirm, verify, and reconcile each approved destination-chain action.

[Read about Kokonut Intelligence](/kokonut-intelligence) and [Kokonut Protocol](/kokonut-protocol) for the governing boundaries.

### Human and DAO authority is non-negotiable

| Agent may prepare | Agent may not independently authorize |
| --- | --- |
| Evidence-gap reports and draft summaries | Verification, publication, or certification |
| Farm plans and budget scenarios | Payments, purchases, or treasury transfers |
| Governance proposals | Governance outcomes or DAO membership changes |
| Unsigned transactions and simulations | Financial signing, contract upgrades, or protected on-chain submissions |
| Public-status summaries from approved records | Disclosure of private farm, stakeholder, or financial information |

The current Kokonut Intelligence agent safety rules deny high-risk actions such as verification, publication, attestation, on-chain submission, and financial writes. An approval-required flag is not itself an execution authorization.

## One identity, chain-specific participation

A single Syntropic Agent can have different ecosystem presences **without issuing a token on every chain**.

| Network | Intended relationship | Token / economics | Maturity |
| --- | --- | --- | --- |
| **Base** | Virtuals agent identity, capital formation, commerce, and ACP | Separate Virtuals-native token and economics | Planned; launch and commercial PRD prepared |
| **NEAR** | Chain-agnostic orchestration hub, protocol interactions, NEAR-native participation | Distinct NEAR token using Nearly's launch mechanics | Planned; design selected |
| **Gnosis** | Existing Kokonut DAO, Baal governance, and Safe state | Existing DAO rights remain separate | Existing infrastructure; agent permissions constrained |
| **Celo** | Existing EAS-backed attestation and provenance workflows | No agent token required | Existing proof infrastructure |
| **Additional chains** | Opt-in Protocol adapters and local services | Token only if justified and separately approved | Future |

**A Base token is not a wrapped NEAR token.** They are separate instruments and do not automatically entitle their holders to the other token's revenues, treasury, governance, farm assets, lease rights, or Kokonut DAO Shares/Loot.

### Planned NEAR token economics

The selected *proposed launch configuration* uses [Nearly](https://nearly.trade/docs) for automated token-tax handling, with Rhea as the underlying trading-liquidity infrastructure.

- **3% buy tax and 3% sell tax** under the selected launch configuration.
- **80% mission development, 10% holder rewards, and 10% direct token burns**, calculated **only over Nearly's creator-controlled allocation of the tax**, not over all gross trade fees.
- Under the reviewed schedule, the creator-controlled allocation was **70% of collected tax**. That implies **56% of gross collected tax to mission development, 7% to holder rewards, and 7% to burns**; the remainder is reserved for the platform/referral allocations.
- Rhea pool creator fees are **separate from the 3% token tax**. The intended policy is to direct actual creator pool-fee receipts to mission development, not silently include them in the 80/10/10 distribution.
- No custom Kokonut holder-distribution vault is planned. Native launchpad mechanics handle rewards and burns, subject to contract-level verification.

<Warning>
  **Not live token terms or financial advice.** Launchpad configuration, supported recipients, automated reward/burn behavior, contracts, liquidity, fees, legal classification, and public disclosures must be verified immediately before launch. The intended mission operator still has legal, tax, governance, custody, and accounting responsibilities for funds it receives. Neither trading volume nor token market capitalization is realized farm income.
</Warning>

## What success looks like

The goal is not simply token issuance or the number of blockchains integrated. It is demonstrable value creation.

| Measure | Evidence-aware success criterion |
| --- | --- |
| Utility | Repeated, accepted work by the Core Team, farm operators, and independent customers |
| Operational improvement | Completed, operator-approved farm milestones with attributable records |
| Economics | Reconciled agent-service receipts and mission expenditures; trading receipts reported separately |
| Ecological outcomes | Evidence-linked and appropriately reviewed soil, biodiversity, production, or resource claims |
| Interoperability | Independently approved, finalized, and reconciled Protocol operations across supported networks |
| Safety | No unauthorized financial execution, privacy breach, or self-verification |
| Community | Meaningful contributions, review participation, and transparent decision-making |

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Is the Syntropic Agent already autonomous?">
    No unrestricted autonomy is intended. It may help prepare and coordinate bounded actions. Protected financial, governance, publication, and evidence decisions require independent authority.
  </Accordion>
  <Accordion title="Does every new chain get an agent token?">
    No. A new chain presence is an adapter and service opportunity first. A chain-native token is optional and must have sufficient utility, economic activity, security, liquidity, and legal justification.
  </Accordion>
  <Accordion title="Do token holders own Kokonut farmland or DAO treasury assets?">
    No automatic ownership or redemption right arises from either planned agent token. Local legal arrangements, DAO membership, and project-specific economic rights are separate.
  </Accordion>
  <Accordion title="Does on-chain data prove a farm impact claim?">
    No. On-chain receipts and attestations can help prove provenance and execution; ecological and operational claims still require appropriate underlying evidence and review.
  </Accordion>
  <Accordion title="Why start with syntropic farming?">
    Syntropic practice connects agricultural design, succession, biodiversity, biomass, water, labor, and production over time. It is a useful real-world laboratory for coordination, provided the outcomes are measured rather than assumed.
  </Accordion>
</AccordionGroup>
